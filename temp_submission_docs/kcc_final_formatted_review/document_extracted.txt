Review-to-Repair에서 변경 위치 파악(change localisation)이 실제 핵심 병목인지, 아니면 복합 요인 중 하나인지를 파일럿 실험으로 점검한다. 기여는 다음과 같다: (1) no_review / direct / gold_location의 3조건 진단 프로토콜 제안, (2) oracle 위치 정보가 위치 중첩 성능은 높이지만 정확 수정률은 개선하지 못한다는 실증, (3) 소규모 오류 분석을 통한 잔여 실패 유형 논의. `r`n `r`n 2. 연구 질문 `r`n RQ1. 리뷰 코멘트는 no_review 대비 수정 성능을 높이는가? `r`n RQ2. oracle 위치 정보는 위치 파악 및 수정 성능을 높이는가? `r`n RQ3. 위치 파악 성능 향상이 정확 수정 향상으로 이어지는가? `r`n RQ4. 위치 정보 개선 후에도 남는 실패 유형은 무엇인가? `r`n `r`n 3. 연구 설계 `r`n 3.1 데이터 및 단위 `r`n 실험 대상은 CodeReview-New로, 코드 스니펫/hunk 단위 벤치마크다. 따라서 gold_location은 full-file이 아닌 within-snippet localisation을 진단한다. 시드 42로 100개 예제를 추출하였으며, 각 예제는 수정 전 코드(old), 리뷰 코멘트(review), 정답 코드(new)로 구성된다. `r`n 3.2 비교 조건 `r`n no_review는 리뷰 코멘트 없이 코드만 제공하는 조건이다. direct는 코드와 리뷰 코멘트를 함께 제공한다. gold_location은 direct에 추가로 정답 변경 위치를 스니펫 내 마커로 표시한다. gold_location은 실제 배포 시스템이 아닌 위치 정보 상한 효과를 검사하는 oracle 진단 조건이다. `r`n 3.3 모델 및 평가 `r`n 주 모델은 qwen2.5-coder:3b (Ollama, 결정론적 디코딩)이다. 강건성 확인을 위해 30개 서브셋에서 qwen2.5-coder:7b도 점검하였다. 평가 지표는 정확 수정 성능(exact_match_line_trim)과 위치 중첩 성능(location_overlap_f1)이며, 조건 간 차이는 paired bootstrap으로 95% 신뢰구간을 계산하였다. `r`n `r`n 4. 실험 결과 `r`n 표 1.
