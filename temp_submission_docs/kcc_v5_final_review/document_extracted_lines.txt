 리뷰 기반 코드 수정에서 변경 위치 파악은 병목인가? 
 CodeReview-New 기반 파일럿 진단 연구 
 Is Change Localisation a Bottleneck in Review-to-Repair? A Pilot Diagnostic Study on CodeReview-New 
 요 약 본 연구는 CodeReview-New의 100개 서브셋을 이용한 파일럿 실험을 통해 변경 위치 파악(change localisation)이 Review-to-Repair에서 주요 관련 요인으로 작용하는지 진단적으로 점검한다. no_review, direct, gold_location의 세 조건을 비교한 결과, direct는 no_review 대비 정확 수정률(exact_match_line_trim)을 0.00에서 0.04로 개선하였다. 반면 gold_location은 위치 중첩 성능(location_overlap_f1)을 0.622에서 0.727로 크게 향상시켰음에도 정확 수정률은 0.03에 머물렀다. 부트스트랩 분석에서 gold_location - direct의 정확 수정률 차이는 -0.010으로 95% 신뢰구간 [-0.040, 0.020]이 0을 포함하였다. 이는 위치 파악이 관련 요인임을 시사하지만, 그것만으로 최종 수정을 보장하지는 않음을 보여준다. 
 키워드: 코드 리뷰, 자동 코드 수정, 대규모 언어모델, 변경 위치 파악, 프로그램 수리 
1. 서 론 
 코드 리뷰 환경에서는 개발자가 자연어 리뷰 코멘트를 바탕으로 코드를 재수정하는 과정이 반복된다. 최근 언어모델 기반 자동 코드 수정 연구는 이 과정을 자동화하려 하지만, 실패 원인이 리뷰 이해 부족인지, 수정 위치 탐지 실패인지, 혹은 패치 생성 실패인지는 충분히 분리 분석되지 않았다. 
 코드 리뷰 자동화 연구에서 Tufano et al.[1]은 코드 리뷰 데이터로 학습한 seq2seq 모델을 이용해 리뷰 코멘트 기반 코드 변경을 처음으로 자동화 과제로 정식화하고, 소규모 코드 변경에서의 초기 자동화 가능성을 보였다. Tufano et al.[2]은 사전학습 언어모델을 코드 리뷰 태스크에 적용하여 코드 정제를 포함한 여러 리뷰 관련 태스크에서의 활용 가능성을 탐색하였다. Li et al.[3]은 대규모 코드 리뷰 데이터를 활용한 다중 목표 사전학습 방식인 CodeReviewer를 제안하고, 리뷰 코멘트 생성·수정 품질 평가·코드 정제를 통합한 학습 체계를 구성하였다. 본 연구와 가장 가까운 선행 연구는 Review4Repair[4]로, 코드 리뷰 코멘트를 자동 프로그램 수리 과정에 직접 통합하여 리뷰 정보가 수리 성능에 미치는 영향을 탐구하였다. 그러나 이들 연구는 공통적으로 end-to-end 성능에 집중하며, 실패가 리뷰 이해·변경 위치 파악·편집 생성 중 어느 단계에서 비롯되는지를 분리 분석하지 않았다. 자동 프로그램 수리 연구[5]에서도 실패 요인 분해의 필요성이 논의되나, Review-to-Repair에 특화된 진단적 분석은 아직 부족하다. 본 연구는 end-to-end 성능 경쟁이 아니라 review understanding·change localisation·edit generation의 세 요인을 조건 통제로 분리하는 diagnostic pilot study라는 점에서 선행 연구와 차별화된다. 
 본 연구는 완성형 시스템 제안 대신 진단적 질문에 집중한다. 기여는 다음과 같다: (1) no_review / direct / gold_location의 3조건 진단 프로토콜 제안, (2) oracle 위치 정보가 위치 중첩 성능은 높이지만 정확 수정률은 개선하지 못한다는 초기 실증, (3) 소규모 오류 분석을 통한 잔여 실패 유형의 잠정적 논의. 단, 본 연구는 어느 단계가 지배적 병목인지를 확정하는 것이 아니라, 변경 위치 파악이 관련 요인으로 작용하는지를 파일럿 수준에서 점검하는 것임을 명확히 한다. 
2. 연구 질문 
 RQ1. 리뷰 코멘트는 no_review 대비 수정 성능을 높이는가? 
 RQ2. oracle 위치 정보는 위치 파악 및 수정 성능을 높이는가? 
 RQ3. 위치 파악 성능 향상이 정확 수정 향상으로 이어지는가? 
 RQ4. 위치 정보 개선 후에도 남는 실패 유형은 무엇인가? 
3. 연구 설계 
 3.1 데이터 및 단위 
 실험 대상은 CodeReview-New로, 코드 스니펫/hunk 단위 벤치마크다. 따라서 gold_location은 full-file이 아닌 within-snippet localisation을 진단한다. 시드 42로 100개 예제를 추출하였으며, 각 예제는 수정 전 코드(old), 리뷰 코멘트(review), 정답 코드(new)로 구성된다. 
 3.2 비교 조건 
 no_review는 리뷰 코멘트 없이 코드만 제공하는 조건이다. direct는 코드와 리뷰 코멘트를 함께 제공한다. gold_location은 direct에 추가로 정답 변경 위치를 스니펫 내 마커로 표시한다. gold_location은 실제 배포 시스템이 아닌 위치 정보 상한 효과를 검사하는 oracle 진단 조건이다. 
 3.3 모델 및 평가 
 주 모델은 qwen2.5-coder:3b (Ollama, 결정론적 디코딩)이다. 강건성 확인을 위해 30개 서브셋에서 qwen2.5-coder:7b도 점검하였다. 평가 지표는 정확 수정 성능(exact_match_line_trim)과 위치 중첩 성능(location_overlap_f1)이며, 조건 간 차이는 paired bootstrap으로 95% 신뢰구간을 계산하였다.

5. 오류 분석 및 논의 
 잔여 실패 원인 파악을 위해 13개 사례(실패 11건, 성공 2건)를 정성적으로 검토하였다. 이 분석은 소규모 표본에 기반하며, 라벨은 체계적인 인적 검증을 거치지 않은 assistant-proposed 잠정 분류다. 따라서 아래 관찰은 강한 정량적 주장이 아니라 탐색적 질적 증거로만 해석해야 한다. 
 gold location이 direct 실패를 정확 성공으로 전환한 사례가 최소 1건 확인되었다. 이는 위치 파악이 일부 사례에서 실패 요인으로 작용할 수 있음을 보여주는 하나의 사례 증거다. 그러나 나머지 실패는 이질적이었다: (a) 목표 위치에 도달했으나 변환을 완성하지 못한 편집 생성 실패, (b) 리뷰 코멘트 해석 실패, (c) 의미상 유사한 출력이지만 snippet-level exact-match 기준으로 실패 처리된 경우. 이러한 이질성은 Review-to-Repair가 위치 탐지 단일 요인으로 환원될 수 없는 복합 과제일 가능성을 시사하지만, 현재 표본 규모로는 이를 단정할 수 없다 (RQ4). 
 5.1 강건성 점검 
 30개 서브셋에서 3B/7B 두 모델 모두 동일한 정성적 패턴이 재현되었다. 또한 seed=7의 별도 100개 서브셋에서 공개 direct 출력의 성능이 원래 서브셋과 유사하여, 초기 서브셋이 극단적 이상치일 가능성은 낮다. 
6. 위협 요인 
 본 연구는 100개 서브셋과 단일 주 모델에 기반하므로 일반화에 한계가 있다. CodeReview-New의 snippet-level 특성상 진단 범위는 within-snippet localisation으로 한정된다. 특히 오류 분석은 13개 소규모 표본에 대한 탐색적 질적 검토이며, 라벨이 체계적 인적 검증을 거치지 않았으므로 잠정적 증거로만 간주해야 한다. exact match 평가가 의미적으로 유효한 패치를 실패로 분류할 수 있다는 점도 한계로 남는다. 
7. 결 론 
 본 연구는 리뷰 코멘트가 no_review 대비 정확 수정에 유용할 수 있음을 보였다. 그러나 oracle 위치 정보는 위치 중첩 성능을 크게 높이면서도 정확 수정률을 개선하지 못하였다. 이는 Review-to-Repair 실패가 위치 파악 단일 요인으로 설명되지 않을 가능성을 시사하는 초기 증거다. 향후 연구에서는 더 큰 표본, 다중 모델 비교, 체계적 오류 라벨링, 스니펫 범위를 넘어선 확장 실험이 필요하다.
